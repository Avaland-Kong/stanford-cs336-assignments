# BPE merge 时三张表怎么更新

## 2026-11-02

### 问题是什么

merge 一对 token 之后，`word_counts` / `pair_counts` 要不要整表重算；受影响的 pair 怎么找；反向索引键变了但 pair 还在时要不要改；左右邻居是否必须单独处理。

### 现象/尝试

一开始认为每次 merge 都要重扫所有 pair。后来意识到只有和合体重叠的关系会变，但不知道怎么从「一对」反查哪些切分键。担心 `(x, u)` 这类仍存在的对也要动反向表，若对全表逐个扫描会不可接受。一度觉得必须分别判断左右邻居。后来改成：对受影响 word 上的旧对全部撤掉，再按新切分把所有对加回去。

### 讨论结论

训练全程维护三张表，职责分开：

- `word_counts`（或 `split_counts`）：当前切分元组 → 该 pre-token 出现次数。键是 `tuple[bytes, ...]`，元素是可变长 `bytes`（单字节或已合并块），不要用 0–255 的 `int`。
- `pair_counts`：相邻两段 `(bytes, bytes)` → 次数。次数要乘上这条切分的出现次数，且不跨 pre-token。
- `pair_to_splits` / `pair_to_words`：`(bytes, bytes)` → **切分键的集合**。这是反向索引，类型是 `dict[tuple[bytes, bytes], set[tuple[bytes, ...]]]`。`pair_counts` 只有次数，没有位置，反查关系必须另存，建 `pair_counts` 的同一遍扫描里登记。

**为什么不能每次全表重算：** 正确，但过不了速度测试，全量 TinyStories 更不行。正确性可以先全量重算；加速后再靠反向表只碰含有当前 pair 的那些键。

**找受影响的切分：** 打开当前要合体的那一对在反向表里的集合即可。不要扫全部 `word_counts`，也不要扫全部还存在的 pair。遍历这个集合前先拷贝，避免边改边遍历。

**范围只在一条 word 内部：** 例如 `x,u,a,b,v,y` 合 `a,b` 之后，只涉及这条序列上的邻对。和这条 word 无关的 pair 不用看。

**次数 vs 反向表：** 次数看「这条碎片还贡不贡献这一对」；反向表看「键的元组变没变」。旧键 `(x,u,a,b,v,y)` 和新键 `(x,u,ab,v,y)` 不是同一对象。`(x,u)`、`(v,y)` 次数可以不变，但集合里必须拿掉旧元组、放上新元组。

**更新策略（比抠左右更稳）：** 对每个受影响 word，用它的次数 `n`：旧序列上每一对从 `pair_counts` 减 `n`、从反向表去掉旧键；按 `(A,B)` 从左到右合体得到新序列；新序列上每一对加 `n`、登记新键；`word_counts` 删除旧键（或扣掉次数），给新键累加 `n`。两条旧切分变成同一新键时次数要加在一起。某对次数到 0 或集合空了，再从表里拿掉。

在反向表正确的前提下，合体后新序列与旧序列不会相同（长度至少少 1）。若相同，说明索引过期。

**同步检查（小例子上每步都可做）：** 用 `word_counts` 慢路径重算 pair 次数和「对 → 哪些键」，与维护的表对比。`word_counts` 次数总和应不变；每个 pair 的次数应等于各 word 的 `freq × 出现次数`；反向表里的键都必须还在 `word_counts` 里且真含有该对；刚合体的那一对次数应为 0 且不在反向表中。

选下一对时用当前 `pair_counts`，平局按原始 bytes 取更大者。`count_pairs` 只在初始建表时走一遍，之后每次 merge 只做增量更新。

### 遗留卡点

主循环、词表 ID、`run_train_bpe` 与 adapter 尚未接上。增量更新是否和讲义小例子逐步一致，要用 `low/lower/widest/newest` 手算核对后再跑 `tests/test_train_bpe.py`。

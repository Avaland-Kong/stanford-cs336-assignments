# 预分词前的文本预处理怎么设计

## 2026-11-01

### 问题是什么

预分词（PDF 那条 GPT-2 regex）之前，原始文本要先怎么切：和 `find_chunk_boundaries` 是不是同一层、special token 切不切开、连在一起的多个标记算一段还是多段、训练和 encode 能否共用、输出该是频率还是保序的段序列。

### 现象/尝试

一开始把「按 special token 切大文件」和「块内再按 special 切开文档」合成一步，又把训练和 encode 都想成「记住位置再按顺序拼回字符串」。后来改成：输出每个文本段的起止位置和性质（普通 / special），训练时忽略 special 段。接着问连在一起的多个标记要不要切开，以及段序列是否必须普通–special 严格交错。

### 讨论结论

预处理和预分词是两层，和官方切块又是另一层。

**三层不要混**

- 大文件切块（可选）：`find_chunk_boundaries`，按字节对齐到某一个 special token，方便并行。块里往往还有多篇文档。小语料可以不做。
- 预分词前预处理（本题）：已经 decode 成 Unicode 字符串之后，按**全部已注册** special token 扫一遍，切成带性质的段。
- 预分词：只对「普通正文」段用同一条 regex 切成 pre-token 字符串。这是训练和 encode 真正共用的那一层。

**预处理函数的契约**

输入是原始 Unicode 文本 + special token 列表。输出是按原文顺序排列的段：每段有起止下标（字符串下标，不是文件字节偏移）和性质（普通正文 / special）。Special 具体是哪一个，用这段切片即可，只要切的时候匹配正确。

一次从左到右扫完，不要每种 special 各搜一遍再合并。正文段两端不含 special。空的正文段可以不输出。

**训练 vs encode**

- 训练：只要普通段，拿去预分词再累计频率。Special 段不进 pair 计数，但 special 仍要**注册进词表**占固定 ID。不是从词表里丢掉，只是不当 BPE 的学习对象。块之间不必保序，计数加总即可。不要把 special 再拼回大字符串。
- encode：普通段和 special 段都要，且必须保序。普通段 → 共用预分词 → 段内 BPE → 若干 ID；special 段 → 一个预留 ID。

共用正则函数只生产 pre-token 字符串（可以惰性），不返回频率表。统计还是保序由调用方决定。

**连在一起的 special 切不切开**

不看「连没连在一起」，看列表里注册了哪些。只注册短的 `<|endoftext|>` 时，粘在一起的两段是两个 special 段。长短都注册时，中间粘在一起的那两段是一个更长的 special 段。测试 `test_overlapping_special_tokens` 和「只注册短标记、连续出现三次」分别对应这两种。

段序列**不必**普通–special 严格交错。允许 special、special 相邻。普通段不应相邻——中间没有 special 就应并成一段再交给正则。

**和 Unicode / 字节的关系**

读文件后就要 decode 成字符串，regex 依赖 `\p{L}` 等。每个 pre-token 再变成 UTF-8 字节是预分词之后、BPE 之前的事，不是预处理层的工作。

### 遗留卡点

扫描时「当前位置多个 special 都能匹配」选哪一个，要以测试为准（更长的整段保留）。实现尚未写，先用 `'Hello, how <|endoftext|><|endoftext|> are you?<|endoftext|>'` 在「只注册短的」和「长短都注册」两种列表下手算应有哪些段，再接到预分词。
